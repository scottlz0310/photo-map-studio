# PhotoMapStudio

写真の EXIF GPS 情報から、撮影地点を中心とした地図画像を生成・一括出力する Windows アプリケーションです。

`PhotoGeoExplorer` / `tacho-graph-studio` と同じトーンで配布する 3 点ツールスイートの 1 つとして開発しています。

> **開発状況**: 初版リリースに向けて実装中です。本リポジトリは [auto-map-generator](https://github.com/scottlz0310/auto-map-generator)（tkinter 実装）の後継であり、仕様と処理アルゴリズムのみを引き継いだ全面リライトです。移行の経緯は [auto-map-generator#10](https://github.com/scottlz0310/auto-map-generator/issues/10) を参照してください。

## 機能

- 入力フォルダ直下、または下位フォルダを再帰探索し、EXIF GPS を持つ写真を列挙する
- 出力先を絶対パス、または各写真フォルダ基準の相対パスで指定する（`.` で写真と同じ場所）
- 出力名の先頭・末尾文字を指定する（既定は `{元写真名}_map.png`）
- 撮影地点を中心とした地図画像を生成し、ピンを合成する
- 出力サイズ・ズームレベル・ピン画像・タイルソースを設定できる
- 列挙・GPS確認・一括生成の進捗、経過時間、取得／キャッシュ件数、キャンセル
- 生成前プレビュー（対象写真の切り替え、設定変更時の自動更新）
- 地図タイルのローカルキャッシュ
- エラー時のローカル診断ログ（最大2MiB、写真・GPS・パス・URLを含めず、外部送信なし）
- 一括生成の実行履歴を端末内へ自動保存（直近30回）。スキップ・エラーの相対パスと理由を過去の実行から確認できる

詳しい使い方はアプリの「ヘルプ」ボタンまたは `F1` で開けます。

対応する入力形式: JPEG / TIFF / HEIC

## 一括生成の履歴

進捗ログの「スキップ・エラーの実行履歴」から実行を選ぶと、元の入力フォルダ、写真の集計、問題の相対パスと理由を確認できます。フォルダを読めなかった場合も対象フォルダを一覧に残します。ファイル名と理由は画面から選択・コピーできます。

完了、キャンセル、連続失敗による中止、開始・継続エラーまでの確定結果を、アプリ保存先 `LocalState/batch-history` に実行単位のJSONで自動保存します。アプリを再起動すると履歴を読み込み、正常保存時に直近30回より古い履歴を自動整理します。保存・読み取り・整理の失敗は履歴欄に表示し、処理済みの写真の件数や今回の結果を変更しません。

履歴には実行日時、入力フォルダ、問題の相対パス・結果・理由、HTTP状態・例外型・HResult、写真の集計を記録します。成功した写真は集計だけを残し、写真本体・GPS・タイルURL・生の例外メッセージは保存しません。これはパスを含めない従来の診断ログとは別の記録です。保存先の実際の場所はヘルプの「トラブルシューティング」で確認できます。

## 地図タイルについて

タイルソースはプリセットから選択できます。生成した画像には出典表示を焼き込みます。

| プリセット | 提供元 | ズーム | 備考 |
| --- | --- | --- | --- |
| **地理院タイル（淡色）** | 国土地理院 | 5–18 | **既定**。日本国内のみ。[地理院タイル一覧](https://maps.gsi.go.jp/development/ichiran.html) |
| 地理院タイル（標準） | 国土地理院 | 5–18 | 日本国内のみ |
| **地理院タイル（最適化ベクトル）** | 国土地理院 | 4–18 | Core内蔵直接描画（PMTiles Range取得）。等高線・道路縁・公的注記。役所提出・調査報告書の参考位置図向け※ |
| **OpenFreeMap（ベクター）** | OpenFreeMap / OSM | 0–19 | Core内蔵直接描画。全世界対応・文字切れのない鮮明な表示。現場確認・民間向け |
| OpenStreetMap | OpenStreetMap contributors | 0–19 | 対話プレビュー用（ラスター）。一括生成は利用条件に合うOSM系配信元をカスタム設定で指定 |

※ **地理院最適化ベクトルタイルの適用範囲と非保証事項**: 写真台帳や調査報告書における「参考位置図・背景案内図」としての利用を想定したものです。国土地理院の最適化ベクトルタイルは測量法に基づく「基本測量成果」そのものとは位置付けられていないため、法的証明や基本測量成果自体の添付が厳密に義務付けられている用途（不動産登記・境界確定等）の証明能力を保証するものではありません。厳密な測量成果が必須の提出先に対しては、別途正規の測量成果交付データ等の確認・利用を案内します。

任意のタイル URL も設定できます（「カスタム」）。さらに「カスタム（ベクター）」では、利用者が用意した配信元を直接描画できます。

- **PMTiles ファイル**（この PC 上の `.pmtiles`。通信しません。収録範囲外の写真でも、撮影地点を外部の配信元へ送らず、プレビューは地図なしの失敗として表示します）
- **PMTiles の URL**（`https://…/*.pmtiles`。HTTP Range 取得）
- **ベクタータイルの URL テンプレート**（`https://…/{z}/{x}/{y}.pbf`。配信する最大ズームを指定します。既定は 14）

レイヤー構成は「OpenMapTiles」または「国土地理院 最適化ベクトル」から選びます。出典表示は必須です。配信元の利用条件・帰属表示は利用者が確認してください。認証情報を URL に埋め込むことはできません。

## コマンドライン連携

スイート連携用に、起動時の入力・出力フォルダを指定できます。既に起動中の場合は同じインスタンスへ引数を転送します。

```text
PhotoMapStudio.exe --input-dir "C:\写真 (2026)" --output-dir maps
```

`--output-dir` の相対指定も各写真のフォルダが基準です。再帰探索と付加文字は画面で設定します。

既定を地理院タイル（淡色）にしているのは、実測（[#8](https://github.com/scottlz0310/photo-map-studio/issues/8)）で次の結果が出たためです。

- 一括生成は OpenStreetMap の Tile Usage Policy が禁じる bulk downloading に該当するが、地理院タイルにこの制限はない
- 写真 20 枚の一括生成が地理院で約 10 秒、OpenStreetMap で約 16 秒（レート制御を含む実測）
- 写真 20 枚で取得するタイル数は、重複除外後で地理院 106 枚、OpenStreetMap 105 枚（大差なし）
- OpenStreetMap はコントラストが高く、ピンが見づらくなる場面がある
- 山間部では地理院タイルの方が地形（等高線など）がわかりやすい

OpenStreetMap を利用する場合は、ローカル PC 上にタイルサーバーを立てる運用を推奨します。設定画面でタイルソースに `http://localhost:8080/tile/{z}/{x}/{y}.png` などを指定することで、一括生成の並列度や待機時間が大幅に緩和されます。

## システム要件

- Windows 10 バージョン 22H2（ビルド 19045）以降、または Windows 11
- x64 または ARM64 プロセッサ
- .NET 10 ランタイム（自己完結型パッケージの場合は不要）

## 開発

```shell
dotnet build PhotoMapStudio.slnx
dotnet test tests/PhotoMapStudio.Core.Tests
dotnet test tests/PhotoMapStudio.App.Tests
```

## アーキテクチャ

Windows App SDK（WinUI 3）によるデスクトップアプリケーションです。ドメインロジック（EXIF 読み取り、Web メルカトル座標変換、タイルキャッシュ、画像合成）は `PhotoMapStudio.Core`（.NET Standard / .NET 10 クラスライブラリ）に分離されており、UI レイヤーに依存しません。

詳細なアーキテクチャ設計仕様は [docs/vector-map-architecture.md](docs/vector-map-architecture.md) を参照してください。

```
PhotoMapStudio/
├── src/
│   ├── PhotoMapStudio.App/     # WinUI 3 デスクトップアプリケーション
│   └── PhotoMapStudio.Core/    # コアドメインライブラリ
├── tests/
│   ├── PhotoMapStudio.App.Tests/
│   └── PhotoMapStudio.Core.Tests/
└── docs/                       # 設計仕様書
```
