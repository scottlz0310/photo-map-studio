# Issue #120: 道路種別（`class`）と実際の路線種別の対応の検証

2026-11-15、Windows x64 / bun 1.4.4 で実施。OSM のデータは 2026-11-14〜15 に Overpass API から取得した。

## 目的

経路番号の盾の種別を決める `OpenMapTilesRoadSymbols.GetShieldKind` は、OpenFreeMap の日本の道路が地域区分を持たないため、道路種別（`class`）で推定している（`trunk`・`primary` は国道、`secondary`・`tertiary` は都道府県道）。この推定が実際の路線種別と合うかを、**OSM でも地理院でもない情報源**で確かめる。

Issue #120 の最初の標本（5 地点・48 本）は、地理院の `RdCL` と突き合わせたものだった。ここでは別の情報源（PLATEAU）を使い、範囲を 8 都市に広げた。この結果を受けた盾の判定の変更は、末尾の追記を参照。

## 正解データ: PLATEAU の道路の機能

国土交通省の 3D 都市モデル（Project PLATEAU）の道路（`tran:Road`）の機能 `tran:function` を正解として使う。コードリスト `Road_function.xml` が、高速自動車国道・一般国道・都道府県道・市町村道を区別する。

- 標準作業手順書（D.3.2.2）では、道路法の区分は「道路管理者から管内図や路線網図を入手して作成する」とされる。形状は都市計画基本図・数値地形図・空中写真測量の成果から作る。地理院の国土基本情報（`RdCL`）や OSM のどちらにも依らない。
- コードリストは配布物に同梱され、内容は自治体や版で変わりうる。スクリプトは ZIP 自身の `codelists/Road_function.xml` を読む。
- **データの癖**:
  - 国道・都道府県道・高速以外は、ほとんどが「不明」（`9020`）になる。「市町村道」（`4`）が使われたのは 8 都市のうち仙台市だけ（51 点）。「不明」は、市町村道と確定したという意味ではない。
  - 路線名（`gml:name`）と路線番号は入っていない。
  - 名古屋市の 2022 年度版は、コードリストにない値 `9` を約 37,700 点で使っている。意味は確認できていない（表では「コード 9（コードリスト外）」と示す）。
  - 整備範囲は自治体ごとで、範囲外の道路は面がない。

## 方法

1. PLATEAU の CityGML の ZIP（数 GB）から、HTTP の Range で道路のファイル（`udx/tran/*.gml`）とコードリストだけを取得する。
2. 道路の LOD1 の面（道路縁で囲まれた範囲）を格子の索引にする。
3. 面の範囲を含む bbox で、OSM の `motorway`〜`tertiary` を Overpass API から取得する。
4. OSM の線を、隣り合う頂点の中点に刻み、各点を含む PLATEAU の面の `tran:function` を引いて、`highway` ごとに集計する（点単位。線の長さにほぼ比例する）。線ごとに点の多数決を取った集計（線単位）も出力する。
5. 交差点などで面が重なる点は「面が重なる」、どの面にも入らない点は「面なし」と別に数え、割合の分母から除く。

### 再現の手順

bun（または Node 22 以降）だけで動く。外部パッケージはない。

```powershell
bun scripts/road-class-validation/validate-road-class.mjs `
  --name kyoto `
  --plateau-zip <上の CityGML の URL> `
  [--cache-dir <作業用フォルダ>] [--json <結果の JSON の出力先>]
```

- 取得したファイルは作業用フォルダ（既定は一時フォルダ）に残り、2 回目以降は再利用する。OSM を取り直すときは、その都市のフォルダの `osm-roads.json` を消す。

- 単体テスト: `bun test scripts/road-class-validation`（CI では実行していない）。

## 読み取れること

- **`primary` を国道とする現在の対応は、8 都市のどこでも外れている。** `primary` が一般国道だった点は、どの都市でも 2.4% 以下だった（最大は京都市）。
- **`primary` → 都道府県道は、5 都市ではほぼ合う。** 福岡市 98%、広島市 97%、京都市 96%、仙台市 91%、鳥取市 81%。一方、**大阪市（26%）・札幌市（42%）・名古屋市（46%）では半分以下**で、残りは「不明」（名古屋市はコード 9）だった。原因が OSM のタグ付けの違いか、PLATEAU の分類の付け方の違いかは確認していない。データは、これらを「市町村道」とは判定していない。
- **`secondary` → 都道府県道**: 66〜98%。大阪市（66%）・札幌市（68%）・名古屋市（71%）で低く、残りの都市は 83% 以上。
- **`trunk` → 国道**: 京都市 100%、福岡市 99%、広島市・仙台市 98% とほぼ合うが、鳥取市 80%、札幌市 66%、大阪市 56%、名古屋市 42% と開きがある。国道以外の多くは「不明」（名古屋市はコード 9）で、高速自動車国道は 7% 以下。
- **`tertiary`**: 国道・都道府県道・高速のどれでもない点が 93〜99%。都道府県道は最大 5.0%（京都市）、国道は最大 2.2%（京都市）。
- **`motorway`**: 高速自動車国道は 33〜99% で都市によって大きく異なる。残りは一般国道（自動車専用道は国道に区分される）や、不明。
- **「面が重なる」点を分母に含めると、割合が下がる都市がある**（福岡市の `trunk` は 98.5% が 77.6% に見える）。このため、重なりは分母から除き、件数だけを別に示している。

## 限界と注意

- **PLATEAU を整備した 8 都市の市街地**（鳥取市は市域の広い範囲）の結果で、農村部・山間部・北海道の郊外は含まない。「地域によって対応が変わる」ことは確認できたが、全国での傾向は分からない。
- 「不明」が多く、市町村道かどうかは確定できない。データが与えるのは「国道か都道府県道か、それ以外か」の区別まで。
- 交差点で面が重なる点は別に数えている（福岡市 3,012 点・広島市 461 点・仙台市 301 点・京都市 258 点）。
- 点は線分の中点で、長い線分では間隔が粗い。OSM のタグ付けは更新されるため、取得日が異なると数値は変わる。
- 面の外周だけを使い、穴は扱っていない。道路縁の面と OSM の中心線は、位置のずれで隣の道路の面に入ることがある。
- 名古屋市のコード 9 の意味は、データの提供元に確認していない。

## 追記: OpenFreeMap の路線関係（`route_N_network`）での判定

上の結果は、`highway`（OpenFreeMap の `class`）から路線種別を推定する方法の限界を示す。その後の確認で、**OpenFreeMap のタイルは路線種別を判断できる属性を持っている**ことが分かった。

### OpenFreeMap のタイルが持つ属性

`transportation_name` レイヤーには、`network`（日本ではほぼ `road`）とは別に、道路が属する路線関係ごとの `route_1_network`〜`route_4_network`・`route_N_ref`・`route_N_name` がある。OSM の路線関係（`route=road`）の `network` がそのまま入る。

| 値 | 意味 |
| --- | --- |
| `JP:national` | 国道 |
| `JP:prefectural`、`JP:prefectural:<地域>` | 都道府県道 |
| `JP:E`、`JP:expressway:*` | 高速道路（高速自動車国道と、一般国道の自動車専用道。標識は緑の「E1」など） |
| `JP:municipal:*`、`JP:city:*` | 市道。`route_N_ref` は内部番号で、盾には使えない |
| `JP:Gokaido` など | 旧街道などの別の経路網 |

国道 53 号と 373 号が重なる道路は、`route_1_ref=53`・`route_2_ref=373` と別々に持つ（`ref` は `53;373`）。

### 照合の方法

OpenFreeMap の z14 タイル（版 `20261101_080013_pt`）を、PLATEAU の範囲に重なる全タイルについて取得し、`transportation_name` の線を点に刻んで、上と同じ方法で PLATEAU の道路の面と照合した。種別の決め方は 2 通りを比べた。

- **路線関係**: `route_N_network` で決める。高速、国道、都道府県道の順に優先する（実装と同じ。`JP:E` と `JP:national` の両方を持つ道路は高速とする）。
- **class 推定（変更前の `GetShieldKind`）**: `motorway` は高速、`trunk`・`primary` は国道、`secondary`・`tertiary` は都道府県道。

PLATEAU の「不明」には、整備が不完全な都市（大阪市・札幌市・名古屋市）で国道・県道が混ざるため、**PLATEAU が国道・県道・高速と明示した点だけ**で、精度（OpenFreeMap がその種別とした点のうち、PLATEAU も同じ種別の割合）と再現率（PLATEAU がその種別とした点のうち、OpenFreeMap も同じ種別とした割合）を求めた。表は「精度 / 再現率」。この照合のスクリプトはこのリポジトリには含めていない（タイルの MVT を読み、線の中点を `lib/plateau-roads.mjs` の索引で引く、小さな使い捨てのもの）。

| 都市 | 路線関係: 国道 | class 推定: 国道 | 路線関係: 都道府県道 | class 推定: 都道府県道 |
| --- | --- | --- | --- | --- |
| 京都市 | 98% / 77% | 40% / 86% | 98% / 80% | 97% / 53% |
| 大阪市 | 96% / 89% | 40% / 95% | 98% / 90% | 97% / 24% |
| 名古屋市 | 85% / 82% | 32% / 89% | 98% / 71% | 96% / 47% |
| 札幌市 | 98% / 93% | 54% / 95% | 100% / 78% | 98% / 49% |
| 鳥取市 | 98% / 75% | 32% / 75% | 100% / 99% | 100% / 55% |

- 路線関係で決めると、国道・都道府県道の精度は 85〜100% になる。class 推定は、国道の精度が 32〜54% で、`primary` の多くを国道と取り違える。
- 路線関係の再現率は 71〜99%。残りは、OSM に路線関係が無い道路で、判定できない。
- 鳥取市の国道の再現率が低いのは、山陰自動車道（E9）など、`JP:E` と `JP:national` の両方を持つ道路を、標識どおり高速の盾にするため（PLATEAU では一般国道）。

### 元の OSM との比較

OpenFreeMap が間引いて路線関係を失っていないかを、Overpass API から取得した元の OSM の路線関係（`rel[route=road][network~"^JP:"]`）と比べた。対象は `motorway`〜`tertiary` の線（OpenFreeMap 側も同じクラスに揃えた）。種別の決め方は上の「路線関係」と同じ。表は「精度 / 再現率」。

| 都市 | 元の OSM: 国道 | OpenFreeMap: 国道 | 元の OSM: 都道府県道 | OpenFreeMap: 都道府県道 |
| --- | --- | --- | --- | --- |
| 京都市 | 100% / 84% | 98% / 81% | 98% / 76% | 98% / 83% |
| 大阪市 | 98% / 96% | 96% / 89% | 99% / 92% | 98% / 90% |
| 札幌市 | 98% / 94% | 98% / 93% | 100% / 80% | 100% / 79% |
| 鳥取市 | 100% / 78% | 98% / 75% | 100% / 98% | 100% / 99% |

精度の差は 2 ポイント以内、再現率の差は最大 7 ポイントで、OpenFreeMap は元の OSM の路線関係をほぼ保っている。元の OSM を別に取得する必要はない（公開の Overpass API は、アプリでは全ユーザーの合計で利用上の目安に数えられ、商用では自前か有償の利用が勧められている。写真の位置を第三者に送ることにもなる）。

### 国道の名称 `国道<番号>号` による判定

Issue #120 の 3 つ目の項目（道路名が `国道<番号>号` の形のとき国道と確定できるか。盾の判定にも使えるか。PhotoGeoExplorer #296 の案）を、同じ方法で確認した。OpenFreeMap の z14 タイル（版 `20261101_080013_pt`）の `transportation_name` の線について、`name` または `name:ja` が正規表現 `(?<!旧)国道\s*[0-9０-９]+\s*号`（「旧国道」は除く）に一致するものを国道とした。都道府県道も、`[都道府県]道N号` の形で同様に確認した。PLATEAU が国道・県道・高速と明示した点だけで、精度と再現率を求めた（この確認のスクリプトも、このリポジトリには含めていない）。

| 都市 | 名称のみ: 国道（精度 / 再現率） | 路線関係のみ: 国道 | 路線関係、無ければ名称: 国道 | 名称が `国道N号` の線のうち、路線関係が無い線 |
| --- | --- | --- | --- | --- |
| 京都市 | 99% / 20% | 98% / 77% | 98% / 79% | 17 / 57 本 |
| 大阪市 | 94% / 62% | 96% / 89% | 96% / 94% | 38 / 171 本 |
| 名古屋市 | 89% / 67% | 85% / 82% | 86% / 89% | 28 / 193 本 |
| 札幌市 | 100% / 35% | 98% / 93% | 98% / 95% | 13 / 92 本 |
| 鳥取市 | 98% / 73% | 98% / 75% | 98% / 75% | 12 / 192 本 |

- 名称による国道の精度は 89〜100% で、路線関係と同じ程度に高い。ただし、名称だけでは再現率が 20〜73% にとどまる。国道でも、名称が通り名（例: 五条通）の道路が多いためとみられる。
- 路線関係を優先し、路線関係が無い道路だけ名称を使うと、国道の再現率は 0〜7 ポイント上がる（京都市 +2、大阪市 +5、名古屋市 +7、札幌市 +2、鳥取市 0）。精度はほぼ変わらない（名古屋市 +1）。名称が `国道N号` の線のうち、路線関係が無いのは 6〜30%。
- 都道府県道の名称は、道路名に `県道N号` の形でほとんど入っておらず（5 都市で 1 本）、使えない。
- この方式は、国道だけに効き、名称の付け方（通称・旧道）に依存する。

### 結論と対応

- 判断できなかったのは OpenFreeMap のデータではなく、描画が読む属性（`network`）と `class` からの推定だった。`GetShieldKind` を、`route_N_network` で決める方式に変更した。
- **路線関係を持たない道路には盾を描かない。** class 推定に戻すと国道の盾を取り違えるため。
- `JP:E` は、高速自動車国道に加えて、一般国道の自動車専用道（例: 山陰自動車道 E9。PLATEAU では一般国道）も含む。どちらも標識は緑の「E」番号なので、高速の盾を描く。`JP:E` と `JP:national` の両方を持つ道路は高速を優先するため、鳥取市の国道の再現率（上の表）は、路線関係をそのまま国道とした場合より低くなる。
- **国道の名称 `国道<番号>号` による確定は、採用しない。** 精度は高いが、効果は国道の再現率で最大 7 ポイントにとどまり、県道には使えない。追加するコード（名称の正規表現と番号の取り出し）と、名称の付け方への依存に見合わない。必要になれば、路線関係が無い道路にだけ使う候補として、`GetRouteShield` に加えられる。

### 限界

- 5 都市・PLATEAU の整備範囲の確認で、農村部・山間部・PLATEAU 未整備の地域は含まない。
- 市道の路線関係（`JP:municipal*`・`JP:city*`）は、盾の判定に使えない。京都市では、そのうち 6〜7 割が PLATEAU で都道府県道だった。
- 路線関係の有無は OSM の整備に依存する。道路ごとの再現率は都市によって 71〜99%。
- 名称による確認（国道）は 5 都市の範囲で、名称の付け方は地域・時期によって変わりうる。
