# photo-map-studio 移植仕様書

本書は [#10](https://github.com/scottlz0310/auto-map-generator/issues/10) で定めた「既存コードは移植せず、仕様と処理アルゴリズムのみ引き継ぐ」方針に基づき、現行 tkinter 実装 (`app/core.py`, `app/services.py`) から**言語非依存のアルゴリズム仕様**を抽出したものである。

後継リポジトリ `photo-map-studio` の `PhotoMapStudio.Core` 実装および単体テストの入力として使う。Python/Pillow 固有の API には依存せず、C# への移植に必要な数値・順序・境界条件のみを記述する。

**本書に記載のない挙動は移植対象外とする。** 現行実装の欠陥として意図的に引き継がないものは §9 に列挙した。

## 1. 用語とスコープ

| 用語 | 定義 |
| --- | --- |
| タイル | Web メルカトル図法の地図タイル。**1 辺 256 px 固定** |
| ズーム `z` | タイルのズームレベル。有効範囲 **1〜19** |
| タイル座標 | ズーム `z` において世界を `2^z × 2^z` 分割した格子上の位置。整数部がタイル番号、小数部がタイル内の相対位置 |
| ワールドピクセル座標 | タイル座標 × 256。ズーム `z` における全世界の画素座標 |
| 出力画像 | 撮影地点を中心とする、指定サイズの地図 PNG |

**重要**: 本ツールは**写真のピクセルデータを一切読まない**。写真から取得するのは EXIF の GPS 座標のみであり、出力画像は地図タイルとピンだけで構成される。したがって HEIC 等のデコーダは不要で、必要なのは**メタデータリーダのみ**である。

移植先で用いるライブラリ（#10 で確定）:

| 責務 | ライブラリ |
| --- | --- |
| EXIF GPS 読み取り | MetadataExtractor 2.9.3（Apache 2.0、純粋 .NET、HEIC 可） |
| タイル合成・ピン合成・文字描画・PNG 出力 | SkiaSharp 4.151.1（MIT、`win-arm64` ネイティブあり） |
| タイル取得 | `HttpClient` + `IHttpClientFactory` |

## 2. 入力ファイルの列挙

### 2.1 対応拡張子

```
.jpg  .jpeg  .tif  .tiff  .heic
```

大文字小文字を区別しない（小文字化して比較する）。

### 2.2 列挙規則

- 入力フォルダ**直下のみ**を走査する。サブフォルダは再帰しない
- ディレクトリエントリは除外し、ファイルのみを対象とする
- 入力フォルダが存在しない、またはディレクトリでない場合は空リストを返す
- **列挙結果はファイル名の昇順にソートする**（§9-1 の是正を含む）

## 3. EXIF GPS 座標の抽出

### 3.1 参照する EXIF タグ

GPS IFD（Exif タグ `0x8825`）配下の以下 4 タグを読む。

| タグ ID | 名称 | 内容 |
| --- | --- | --- |
| `1` | GPSLatitudeRef | `"N"` または `"S"` |
| `2` | GPSLatitude | 度分秒の 3 要素（各要素は有理数） |
| `3` | GPSLongitudeRef | `"E"` または `"W"` |
| `4` | GPSLongitude | 度分秒の 3 要素（各要素は有理数） |

**4 つすべてが揃っていない場合、その写真は GPS 情報なしとして扱う**（部分的な値からの推定は行わない）。

### 3.2 DMS → 十進度 (Decimal Degrees) 変換

入力は 3 要素の有理数列 `[d, m, s]`。各要素は `分子/分母` の有理数、または単一の数値として与えられる。

```
value(x) = x.numerator / x.denominator   (denominator ≠ 0 の場合)
         = x.numerator                   (denominator = 0 の場合)
         = x                             (x が単一数値の場合)

dd = value(d) + value(m) / 60 + value(s) / 3600

ref が "S" または "W" のとき: dd = -dd
```

境界条件:

- 要素数が 3 未満、または列が空の場合は `0.0` を返す
- 分母が 0 の場合はゼロ除算を避け、分子をそのまま値とする

### 3.3 エラー時の扱い

現行実装は例外を握りつぶして `None` を返している。**移植先では「GPS 情報が存在しない」と「読み取りに失敗した」を区別する**（§9-2）。

## 4. 座標変換（Web メルカトル）

緯度経度 `(lat, lon)`（十進度）とズーム `z` から、**浮動小数点のタイル座標** `(tileX, tileY)` を求める。

```
n = 2^z

tileX = (lon + 180) / 360 × n

latRad = lat × π / 180
tileY  = (1 - ln(tan(latRad) + 1 / cos(latRad)) / π) / 2 × n
```

これは OSM/Slippy Map の標準式であり、`ln(tan(φ) + sec(φ)) = asinh(tan(φ))` と等価である。C# では数値安定性のため `Math.Asinh(Math.Tan(latRad))` を用いてよい（結果は同値）。

ワールドピクセル座標への変換:

```
worldPxX = tileX × 256
worldPxY = tileY × 256
```

## 5. タイル取得とキャッシュ

### 5.1 URL テンプレート

既定値:

```
https://tile.openstreetmap.org/{z}/{x}/{y}.png
```

`{z}` `{x}` `{y}` を整数値で置換する。テンプレートはユーザー設定で変更可能（FR-03）。

### 5.2 キャッシュキー

```
cacheFileName = "{urlHash}_{z}_{x}_{y}.png"
urlHash       = MD5(URL テンプレート文字列, UTF-8) の16進小文字表現の先頭 8 文字
```

**URL テンプレート全体をハッシュに含めることで、タイルソースを切り替えてもキャッシュが混ざらない**（FR-07 の要件）。ハッシュ対象は置換前のテンプレート文字列であり、置換後の個別 URL ではない。

> 移植時の注記: MD5 は衝突耐性を要求されない用途（キャッシュのディレクトリ分離）でのみ使っている。セキュリティ用途ではないが、.NET のアナライザ設定 (`AnalysisMode=AllEnabledByDefault`) では `CA5351` に抵触するため、SHA-256 の先頭 8 文字へ変更してよい。**その場合キャッシュ互換性は失われるが、設定移行を行わない方針（#10 決定事項）のため問題ない。**

### 5.3 キャッシュ動作

1. キャッシュファイルが存在すれば読み込んで返す
2. 読み込みに失敗した場合はキャッシュを無視してネットワーク取得へ進む
3. 取得成功時は**レスポンスのバイト列をそのまま**キャッシュに書き出す（再エンコードしない）

保持期間について、現行実装は**無期限**。OSM Tile Usage Policy は「サーバのキャッシュヘッダを尊重、読めない場合は最低 7 日保持」を要求しているため、下限は満たす。移植先ではキャッシュヘッダの尊重を検討する。

### 5.4 HTTP 要求

- `User-Agent` にアプリを識別する固有の値を設定する（NFR-NET-02）。ライブラリ既定値は OSM でブロック対象
- 現行値 `AutoMapGenerator/1.0 (https://github.com/scottlz0310/PhotoGeoExplorer)` は**参照 URL が誤っている**（別リポジトリを指している）。移植時に是正する（§9-3）

### 5.5 取得失敗時

現行実装は `(220, 220, 220, 255)` の単色 256×256 タイルを返し、**失敗を呼び出し元に伝えない**。移植先では是正する（§9-2）。

## 6. 地図画像の合成

入力: 中心座標 `(lat, lon)`、出力サイズ `(width, height)`、ズーム `z`、タイル URL テンプレート

### 6.1 必要タイル範囲の決定

```
centerPxX = tileX(lat, lon, z) × 256
centerPxY = tileY(lat, lon, z) × 256

leftPx   = centerPxX - width  / 2
topPx    = centerPxY - height / 2
rightPx  = centerPxX + width  / 2
bottomPx = centerPxY + height / 2

minTileX = floor(leftPx   / 256)
maxTileX = floor(rightPx  / 256)
minTileY = floor(topPx    / 256)
maxTileY = floor(bottomPx / 256)
```

`floor` は**負値に対しても床関数**（−0.3 → −1）であること。C# の整数除算やキャストは 0 方向への切り捨てになるため、`Math.Floor` を使うこと。

### 6.2 キャンバスの構築

```
canvasW = (maxTileX - minTileX + 1) × 256
canvasH = (maxTileY - minTileY + 1) × 256
```

RGBA のキャンバスを確保し、`minTileY..maxTileY` × `minTileX..maxTileX` の全タイルを取得して、次の位置に配置する。

```
posX = (tx - minTileX) × 256
posY = (ty - minTileY) × 256
```

タイルは**アルファ合成せず上書き**で配置する（重なりがないため差は生じない）。

### 6.3 切り出し

```
cropLeft = leftPx - minTileX × 256
cropTop  = topPx  - minTileY × 256
```

`(cropLeft, cropTop)` を左上とする `width × height` の領域を切り出す。結果が出力画像の素地となる。

`cropLeft` / `cropTop` は小数値になりうる。現行実装（Pillow）は整数に切り捨てられる。**移植先でも切り捨てとし、サブピクセル補間は行わない**（タイル境界のにじみを避けるため）。

### 6.4 ピンの合成

ピンは出力画像の中心 `(cx, cy) = (width / 2, height / 2)` に対して配置する。

```
pinLeft = round(cx - pinWidth / 2)
pinTop  = round(cy - pinHeight)
```

**アンカーはピン画像の「下端中央」**であり、ピンの先端が撮影地点を指す。ピン画像はアルファチャンネルをマスクとして合成する。

既定のピン画像は `assets/green_pin.png`。ユーザー設定で差し替え可能（FR-03）。

### 6.5 フォールバックピン

ピン画像が未指定・不存在・読み込み失敗の場合、以下を中心 `(cx, cy)` に描画する。同心円 3 枚を順に重ねる。

| 順 | 形状 | 塗り (RGBA) | 輪郭 (RGBA) | 線幅 |
| --- | --- | --- | --- | --- |
| 1 | 半径 12 の円 | `(255, 255, 255, 255)` | `(100, 100, 100, 255)` | 1 |
| 2 | 半径 10 の円 | `(235, 59, 36, 255)` | `(180, 20, 20, 255)` | 1 |
| 3 | 半径 3 の円 | `(255, 255, 255, 255)` | なし | — |

注: 1 枚目の半径は `pinRadius + 2 = 12`、2 枚目が `pinRadius = 10`。この場合のアンカーは**円の中心**であり、ピン画像使用時（下端中央）とは異なる。

### 6.6 attribution の焼き込み

現行実装には存在せず、#10 の FR-08 として新規に追加する要件。**生成画像への焼き込みを必須とする**（プレビュー画面上の表示も別途必要）。

- 位置は出力画像の**右下**
- 半透明の下地の上にテキストを描画し、地図の内容に紛れて読めなくならないようにする
- 既定文字列は `© OpenStreetMap contributors`
- 任意タイル URL（FR-03）に対応するため、**文字列は設定可能**とする

出力サイズが極端に小さい場合の扱い（縮小するか省略するか）は実装時に決める。

日本語を含む文字描画が必要になりうるため、合成ライブラリには **SkiaSharp 4.151.1**（MIT）を用いる。tacho-graph-studio が同じ理由で採用している。

## 7. 一括生成フロー

入力: 入力フォルダ、出力フォルダ、`width`, `height`, `zoom`, ピンパス、タイル URL、進捗コールバック、キャンセル判定

### 7.1 手順

1. §2 の規則で対象ファイルを列挙する。0 件なら `(成功 0, スキップ 0, 総数 0)` を返して終了
2. 出力フォルダを作成する（既存なら何もしない、親も含めて作成）
3. 各ファイルについて `1` 始まりの連番 `idx` を付与し、順に処理する
   1. **キャンセル要求があれば** `CANCELLED` を通知して**ループを中断**する（残りは処理しない）
   2. EXIF GPS を抽出する。取得できなければスキップ数を +1 し、`SKIP` を通知して次へ
   3. §6 の手順で地図を合成する
   4. `{元ファイル名の拡張子なし}_map.png` として出力フォルダに PNG 保存する
   5. 成功数を +1 し、`SUCCESS` を通知する
   6. 例外が発生した場合は `ERROR` を通知し、**成功数・スキップ数のいずれも加算せず**次のファイルへ進む
4. `(成功数, スキップ数, 総数)` を返す

### 7.2 進捗コールバックの契約

`(idx, total, fileName, status, message)` を渡す。`status` は次の 4 値。

| status | 意味 | message の例 |
| --- | --- | --- |
| `SUCCESS` | 生成成功 | `位置情報 (35.68123, 139.76712) -> IMG_0001_map.png を作成しました。` |
| `SKIP` | GPS 情報なし | `GPS情報が見つかりません。` |
| `ERROR` | 生成中の例外 | `生成エラー: {例外メッセージ}` |
| `CANCELLED` | キャンセルによる中断 | `処理が手動でキャンセルされました。` |

緯度経度は**小数点以下 5 桁**で表示する。

### 7.3 キャンセルの粒度

現行実装のキャンセル判定は**ファイル単位**であり、1 枚の合成中（タイル取得中）は中断できない。#10 の NFR-UI-03 は `CancellationToken` によるタイル取得レベルの即時中断を要求しており、**この点は仕様を引き上げる**。

### 7.4 出力名の衝突

`IMG_0001.jpg` と `IMG_0001.heic` が同一フォルダにある場合、いずれも `IMG_0001_map.png` に出力され、**後勝ちで上書きされる**。現行実装は検出しない。移植時の扱いは §9-4。

## 8. プレビュー生成

単一の写真から地図を合成する。バリデーションを**この順序で**行い、最初に失敗した時点で該当メッセージを返す。

| 順 | 条件 | 失敗時メッセージ |
| --- | --- | --- |
| 1 | `width > 0` かつ `height > 0` | `画像サイズ(幅・高さ)は正の整数を指定してください。` |
| 2 | `1 ≤ zoom ≤ 19` | `ズームレベルは 1 〜 19 の範囲で指定してください。` |
| 3 | 対象画像が選択されている | `プレビュー対象の画像が選択されていません。` |
| 4 | 対象画像が実在するファイルである | `指定された画像ファイルが存在しません。` |
| 5 | GPS 情報が取得できる | `選択された写真にGPS情報が含まれていません。` |
| 6 | 合成が成功する | `プレビュー生成エラー: {例外メッセージ}` |

成功時のメッセージは `緯度: {lat:.5f}, 経度: {lon:.5f}`。

結果は「画像」「座標」「メッセージ」「成否」の 4 項目を持つ不変オブジェクトとして返す。**座標は GPS 取得後に失敗した場合（順 6）にも保持する**。

### 8.1 既定値

| 項目 | 既定値 |
| --- | --- |
| `width` | 800 |
| `height` | 600 |
| `zoom` | 15 |
| ピン | `assets/green_pin.png` |
| タイル URL | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` |

## 9. 引き継がない現行実装の欠陥

移植先で**是正する**もの。現行の挙動をそのまま再現してはならない。

| # | 欠陥 | 是正方針 |
| --- | --- | --- |
| 1 | 一括生成 (`process_images`) はフォルダ列挙順のまま処理し、プレビュー用一覧 (`list_gps_images`) だけがソートしている。処理順が OS 依存で非決定的 | **両者を名前昇順ソートに統一する**。テストの再現性にも必要 |
| 2 | `extract_gps_location` と `fetch_tile` が例外を握りつぶす。タイル取得失敗はグレー単色タイルとして出力画像に混入し、ユーザーに通知されない | **エラーはコンテキストを付けて呼び出し元に伝播させる**。取得失敗時に無言でグレータイルを描き込まない |
| 3 | `USER_AGENT` の参照 URL が別リポジトリ (`PhotoGeoExplorer`) を指している | `photo-map-studio` の URL とアプリ名・バージョンを表明する。NFR-NET-02 のとおり単一プロバイダで一元管理する |
| 4 | 拡張子違いの同名写真で出力ファイルが無言で上書きされる | 検出して衝突回避（連番付与）またはユーザーへの通知を行う |
| 5 | attribution が一切存在しない | FR-08 として実装する。プレビュー表示と生成画像への焼き込みの両方（§6.6） |
| 6 | タイルキャッシュが無期限 | キャッシュヘッダの尊重を検討する。最低 7 日は現行でも満たしている |
| 7 | 一括生成が OSM の bulk downloading 定義に該当しうる | #10 の判断ポイント 3 の結論に従う |

## 10. 単体テストの推奨ケース

`PhotoMapStudio.Core.Tests` で押さえるべき境界。パラメータ化テストを基本とする。

### 10.1 DMS → DD 変換

| 入力 | 期待値 |
| --- | --- |
| `[35, 40, 52.2]`, `"N"` | `35.681166...` |
| `[35, 40, 52.2]`, `"S"` | `-35.681166...` |
| `[139, 46, 1.6]`, `"E"` | `139.767111...` |
| `[139, 46, 1.6]`, `"W"` | `-139.767111...` |
| 要素数 2 の列 | `0.0` |
| 空の列 | `0.0` |
| 分母 0 を含む要素 | ゼロ除算を起こさず分子を採用 |

### 10.2 タイル座標変換

| 入力 | 期待値 |
| --- | --- |
| `lat=0, lon=0, z=0` | `(0.5, 0.5)` |
| `lat=0, lon=-180, z=0` | `(0.0, 0.5)` |
| `lat=0, lon=180, z=0` | `(1.0, 0.5)` |
| `lat=85.0511, lon=0, z=0` | `y ≈ 0.0`（メルカトルの北限） |
| `lat=-85.0511, lon=0, z=0` | `y ≈ 1.0`（南限） |
| `z=19` の任意座標 | オーバーフローしない |

### 10.3 タイル範囲の決定

- **経度 0 度・緯度 0 度をまたぐ**場合に `minTileX` が負になり、`floor` が正しく機能すること
- 出力サイズがタイル 1 枚 (256) より小さい場合に、タイルが 1〜2 枚に収まること
- 出力サイズが 256 の倍数ちょうどの場合の枚数

### 10.4 キャッシュキー

- 同一タイル座標でも**URL テンプレートが異なればキーが異なる**こと
- 同一 URL テンプレート・同一座標でキーが一致すること

### 10.5 合成

- ピン画像のアンカーが**下端中央**であること（`pinTop = cy - pinHeight`）
- ピン画像が存在しない場合にフォールバック描画へ切り替わること
- 切り出し領域が指定した `width × height` に一致すること

タイル取得はネットワーク依存のため、**`IHttpClientFactory` またはタイル取得インターフェースを注入してモック可能にする**（CLAUDE.md のテスト規約）。
